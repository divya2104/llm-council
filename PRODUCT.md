# Product

## Register

product

## Platform

web

## Users

Two audiences share this tool. The primary is anyone (currently the project owner) using LLM Council to get a higher-quality answer than a single model would give — asking a question, reading individual model responses, and seeing how the models rank each other before a chairman model synthesizes a final answer. The secondary is HR at Aditya Birla Group, using the JD Creator wizard to draft structured, Hay-methodology job descriptions for ABSLAMC and NBFC entities (accountabilities, dimensions, sign-off) instead of starting from a blank document.

## Product Purpose

LLM Council's core purpose is cross-model deliberation: instead of trusting one LLM's answer, it queries several in parallel, has them anonymously peer-review each other's responses, and has a chairman model synthesize a final answer from the full deliberation. JD Creator is a secondary workflow built on the same app shell, turning job description authoring into a guided, policy-compliant wizard for HR.

## Positioning

Cross-model deliberation, not one opinion — anonymized peer review across multiple LLMs, synthesized by a chairman model, with every step's raw output inspectable rather than hidden behind a single black-box answer.

## Brand Personality

Modern and a little colorful, but considered rather than flashy — confidence through restraint, not gloss. The existing editorial pairing (serif display + clean sans body, muted earthy palette with one clear brand accent) is the right register: it should feel rigorous and transparent, never like a templated AI-wrapper or a dated enterprise HR tool.

## Anti-references

Not a generic SaaS / ChatGPT-clone look (gradient heroes, cream/sand backgrounds, hero-metric cards, tiny uppercase eyebrows). Not heavy corporate enterprise software either (dense toolbars, grey-on-grey, unstyled defaults).

## Design Principles

- Transparency over black-box: raw model outputs and parsed rankings are always inspectable, so users can validate the system's interpretation rather than trust it blindly.
- Structure without rigidity: guided flows (the ranking format, the JD wizard's steps) enforce consistency and policy compliance without feeling like enterprise software.
- Considered, not flashy: modern and a little colorful, but restrained — earn attention through clarity, not decoration.
- Graceful degradation: the product keeps working and stays legible when part of it fails (a model errors out, a DB connection drops), rather than failing the whole request.

## Accessibility & Inclusion

Standard WCAG AA: sufficient contrast, keyboard navigability, and reduced-motion support. No unusual or specialized accessibility requirements beyond that.
